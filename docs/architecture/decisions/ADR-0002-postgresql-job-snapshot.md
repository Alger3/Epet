# ADR-0002：PostgreSQL 任务快照是状态事实来源

> 状态：Accepted
> 负责人：后端负责人
> 评审人：桌面端负责人、Worker 负责人
> 日期：2026-07-24
> 取代：无
> 被取代：无

## 背景

生成任务持续数分钟，客户端、API、Worker 与队列会重启或断连。依赖 Redis/SSE 回放会在丢消息、乱序和过期时产生不一致。

## 决策

PostgreSQL 保存任务当前快照、单调递增 `version`、阶段、时间、错误和尝试版本。Redis 只用于队列、锁和变化通知；SSE 只通知有新版本。客户端首次连接、重连、版本跳号或超时后调用 GET 获取完整快照，并只接受更高版本。

## 代价与后果

- 丢失通知不会丢失最终状态，任务可审计和恢复。
- 每次状态转换必须先在数据库事务提交，之后才能发布通知。
- API 和 Worker 需要乐观锁、幂等与重复消息处理。

## 重新评审条件

若 PostgreSQL 无法满足经实测的写入或恢复目标，候选替代必须提供同等持久性、版本顺序、事务边界和迁移方案。
