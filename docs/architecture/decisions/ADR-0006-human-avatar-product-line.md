# ADR-0006：加入 Q 版人物桌宠产品线

> 状态：Accepted
> 负责人：产品负责人、技术负责人
> 评审人：桌面端负责人、后端/AI 负责人、测试/安全负责人
> 日期：2026-07-24
> 取代：无
> 被取代：无

## 背景

首版原计划只从猫咪照片生成桌宠。产品范围现明确要求同时支持 Q 版人物桌宠。人物照片涉及身份、授权、未成年人、公众人物和内容安全，若直接在原猫咪请求中增加大量可选字段，会让契约、流水线路由、质量评估和删除责任变得含糊。

当前项目仍处于阶段 2，人物生成尚未实现。本 ADR 固定后续实现边界，不把计划状态表述为现有能力。

## 决策驱动因素

- 猫咪与人物输入特征、生成约束和失败类型明显不同；
- 任务查询、下载、资源包和桌面运行时可以安全复用；
- 人物必须有独立的授权、安全、质量、成本和回滚控制；
- 已安装猫咪 Schema v1 包及阶段 2 桌面壳不能因范围扩大而失效。

## 决策

MVP 包含 `pet_cat` 与 `human_avatar` 两条产品线，同时只激活一个桌面角色。狗及其他动物仍不在首版。

1. 创建入口分为 `POST /v1/pet-generations` 与 `POST /v1/avatar-generations`。创建后共享 `/v1/generations/{job_id}` 的查询、事件、确认、重试、取消、下载和删除接口。
2. `PetGenerationPipeline` 使用 `pet_spec` 和 Gate B-P；`HumanAvatarGenerationPipeline` 使用 `human_spec` 和 Gate B-H。两者拥有独立请求 Schema、门禁、模型/提示配置、评估集、成本预算和功能开关。
3. PostgreSQL 任务快照、对象存储生命周期、队列基础设施、`.epet` 打包器、客户端安全安装与 Sprite Atlas 运行时保持共享，任务以不可变 `subject_kind` 路由。
4. 人物 MVP 只接受上传者本人或已获明确授权的成年人；疑似未成年人、公众人物、未经授权第三方、多人合照、写实换脸和成人内容拒绝处理。
5. 授权记录只保存声明 ID、文案版本、时间和设备凭据关联，不收集身份证件，不把人脸向量、年龄或敏感属性写入通用日志。
6. 角色包升级为 Schema v2 判别联合。客户端只读兼容已有猫咪 Schema v1 包；本地 `pets` 数据迁移为 `characters` 并标记 `pet_cat`，不原地改写旧资源包。
7. `human_avatar_enabled` 默认关闭，只有 Gate B-H、安全评审、授权撤回和删除演练通过后才开启。关闭人物线不得影响猫咪新任务或任何已安装角色的离线运行。

## 代价与后果

- 三人团队封闭 Alpha 目标由 14 周调整为 18 周，公开灰度另计 2–4 周。
- 需要人物专属 UI 授权步骤、OpenAPI/Schema、Worker、质量量表、安全集、监控和运行手册。
- 两个创建入口增加少量 API 表面积，但避免一个请求体出现互斥字段和错误路由。
- 指标、成本、成功率和 Gate 结果必须按 `subject_kind` 分开，不能用合并平均掩盖某条产品线失败。

## 验证证据

待验证。Gate B-H 至少使用 20 组探索照片和 50–100 组获授权成年人冻结评估照片；目标是整体可用率不低于 80%、严重结构错误率不高于 5%，并通过安全拒绝、授权撤回和派生资源删除演练。

## 重新评审条件

- 需要支持未成年人、公众人物、多人物、写实人像、换脸或成人内容；
- 人物 Gate B-H、隐私删除或单角色成本在两轮正式评估后仍不达标；
- Schema v1 兼容导致不可接受的运行时复杂度；
- 团队人数、目标平台或首发时间发生足以改变 18 周排期的变化。
