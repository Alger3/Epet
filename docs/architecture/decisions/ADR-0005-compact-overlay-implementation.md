# ADR-0005：采用小尺寸窗口与原生窗口移动

> 状态：Accepted
> 负责人：桌面端负责人
> 评审人：技术负责人、测试负责人、安全负责人
> 日期：2026-07-24
> 最近验证：2026-07-25
> 取代：无
> 被取代：无

## 背景

[ADR-0004](ADR-0004-overlay-window-model.md) 只确定使用透明置顶悬浮窗口，要求小窗口/大 Overlay、窗口移动频率和 Win32 样式经过 Windows Spike 后另行记录。阶段 2 需要一个可运行实现用于收集证据，但当前尚无目标 Windows 的性能和长稳结果。

## 提议决策

阶段 2 原型采用随宠物尺寸缩放的小型方形 Tauri 窗口；用户拖动调用原生 `start_dragging`，位置写入 250 ms 防抖。Windows 增加 `WS_EX_NOACTIVATE` 与 `WS_EX_TOOLWINDOW`，Tauri 配置同时使用无边框、置顶、跳过任务栏和初始不聚焦。

窗口移动而不是只移动 PixiJS 内部 Sprite。缩放以宠物脚底为锚点，窗口坐标始终由 Rust 使用物理像素、工作区和 DPI 换算。完全穿透使用原生 `set_ignore_cursor_events`，托盘保留恢复入口。

Gate A 实现采用独立 Rust 时钟以 10 Hz 移动系统窗口，速度按显示器 DPI 换算，沿工作区底部水平移动并在边界反向；CSS/Sprite 动画不负责系统窗口坐标。暂停、隐藏和拖拽优先于移动，位置至少每秒持久化。多 DPI、多屏、热插拔、命中、焦点和长稳矩阵已在 2026-07-25 完成验收。

## 备选方案

1. 全屏/大范围透明 Overlay：行为路径简单，但命中测试、GPU 合成、全屏应用干扰和多屏资源占用风险更高。
2. 固定窗口只移动内部 Sprite：不能跨越固定边界，不满足桌面移动需求。
3. 注入 WorkerW/桌面图标层：依赖未文档化行为，已由 ADR-0004 排除。

## 预期后果

- 原生窗口尺寸和重绘区域较小，理论上资源占用更可控；
- 需要处理跨屏窗口移动、DPI 跳变、透明命中和频繁位置事件；
- `WS_EX_NOACTIVATE` 可能影响部分交互，必须在穿透开关、拖动和焦点矩阵中验证；
- 该窗口模型已通过 Gate A；后续若改为大 Overlay、桌面图标层或改变原生坐标模型，必须新增 ADR 并重新执行适用矩阵。

## 接受条件

- Windows 11 在 100/125/150/200% DPI、左右/上下双屏和热插拔用例通过；
- 不抢焦点、任务栏/Alt-Tab 隐藏和穿透恢复入口通过；
- 与大 Overlay 原型比较 CPU、GPU、内存和交互正确性；
- 八小时运行无阻断问题；
- 评审后将状态改为 Accepted，或新增替代 ADR 并保留失败原因。
