# ADR-0004：使用透明置顶悬浮窗口

> 状态：Accepted
> 负责人：桌面端负责人
> 评审人：产品负责人、安全负责人
> 日期：2026-07-24
> 取代：无
> 被取代：无

## 背景

桌宠需要出现在普通应用上方，同时不破坏桌面、焦点和系统兼容性。把窗口注入未文档化 WorkerW/桌面图标层会依赖不稳定内部行为。

## 决策

产品采用透明、无边框、置顶的普通悬浮窗口，不嵌入壁纸层或桌面图标层。全屏、锁屏和安全界面允许隐藏或暂停。托盘始终保留显示、隐藏、穿透和退出入口。

小尺寸窗口或更大 Overlay、系统窗口移动频率、`WM_NCHITTEST` 与具体 Win32 样式必须经阶段 0 Windows Spike 后记录新的实施 ADR；本决策不声称这些细节已验证。

## 代价与后果

- 使用文档化窗口模型，安装和系统兼容风险更可控。
- 需要处理透明区域命中、多屏、DPI、焦点和 Alt-Tab 行为。
- 全屏应用上方显示不作为绝对承诺，可按性能和干扰策略暂停。

## 重新评审条件

只有文档化 Windows API 无法达到 Gate A，且替代方案通过安全、兼容、更新和卸载评审时重新评审；未文档化注入方案不作为默认降级。
