# ADR-0001：客户端只运行 Sprite Atlas

> 状态：Accepted
> 负责人：桌面端负责人
> 评审人：后端/AI 负责人、产品负责人
> 日期：2026-07-24
> 取代：无
> 被取代：无

## 背景

MVP 需要可预测的性能、包大小和安全边界。骨骼、网格、模型权重或生成脚本进入客户端会扩大运行时、授权和攻击面。

## 候选方案

- Sprite Atlas：统一烘焙逐帧资源，客户端只解析纹理与动作清单。
- 客户端骨骼/网格：包更灵活，但运行时和格式复杂。
- Live2D：能力成熟，但自动制模质量、授权和集成超出 MVP。

## 决策

MVP `.epet` 只声明 `renderer: sprite_atlas`。服务端可以在内部使用骨骼、网格或插值，但最终必须烘焙为 Sprite 帧。动作顺序、时长、循环和 fallback 只由 manifest 定义。

## 代价与后果

- 客户端资源加载和安全校验更简单；预览与桌面共用运行时。
- 每个动作可能增加纹理体积，需执行 30 MB 包限制和纹理复用。
- 高级可变形互动延后，不为未来能力提前扩展格式。

## 重新评审条件

只有 Sprite Atlas 无法达到已批准交互目标，且新格式通过性能、安全、许可证、迁移和降级评审时重新评审。
