# 部件拆分、骨骼动画与 Atlas 流水线

> 实现状态：5.4 基线已于 2026-07-27 完成。当前 Mock 使用程序化 LayerBundle 验证猫咪与人物 Rig、六动作 Clip、确定性 Atlas 和桌面距离相位；真实照片到标准立绘/部件 Mask 的 Provider 属于步骤 5.5。

> 状态：Planned
> 首次实施位置：阶段 5.4
> 运行时边界：客户端继续只加载 `.epet` Sprite Atlas v1

## 1. 目标与边界

当前 Mock Worker 为每个动作写入同一张静态图片，因此角色虽然会随窗口移动，却没有脚步、
尾巴、呼吸、眨眼和姿势变化。本方案在生成模型之前先建立可独立验证的动画资产流水线：

```text
标准透明立绘
→ 部件层与遮挡补全
→ 模板骨骼绑定
→ 程序化动作片段
→ 固定步长离线渲染
→ 确定性 Atlas
→ 现有 .epet 校验、安装和运行
```

骨骼、部件图、蒙皮和动画脚本只存在于 Worker 制作阶段。最终客户端仍只接收图片帧、
Atlas JSON 和 manifest，不下载模型权重，也不在桌面运行时执行骨骼求解。

第一轮先使用受控测试角色和人工准备的部件层验证动画；OpenVINO/CUDA 模型 Provider
顺延到动画基线之后，再负责生成标准立绘和可供拆分的遮罩。

## 2. 中间资产契约

中间资产使用版本化 Schema，禁止用未校验的自由 JSON 在步骤之间传递。

### 2.1 `LayerBundle`

至少包含：

- 画布宽高、脚底基线和角色中心线。
- 部件 ID、图片路径、Alpha Mask、Z 顺序和默认可见性。
- 部件在标准姿势中的包围盒、连接点和旋转中心。
- 遮挡补全区域、边缘扩展像素和来源类型（原始可见、模型补全、模板补全）。
- 主体类型、身份版本、拆分器版本和输入摘要。

猫咪首版部件：

- `torso`、`head`。
- 左右耳与睁眼/闭眼层。
- 左右前腿、前爪、后腿和后爪。
- 4 段尾巴；长毛猫可增加尾尖覆盖层。
- 可选饰品层和地面阴影层；阴影不参与角色命中区域。

人物首版部件：

- `pelvis`、`torso`、`head`。
- 后发、前发、睁眼/闭眼和嘴型层。
- 左右上臂、前臂、手、大腿、小腿和脚。
- 服装前层、服装后层和可见配饰层。

### 2.2 `RigDefinition`

至少包含：

- 骨骼 ID、父骨骼、静止位置、长度、默认角度和角度限制。
- 部件与骨骼的绑定、旋转中心、局部偏移和 Z 顺序规则。
- `foot`、`drag`、身体中心和头部观察点锚点。
- 归一化碰撞区域。
- 模板 ID、模板版本、适用主体和体型。

首版采用刚性部件旋转、缩放和少量剪切，不立即实现通用网格蒙皮。头发、衣摆和长毛边缘
需要柔性变形时，先使用 2–3 段附属骨骼；只有刚性方案出现明确质量瓶颈后才引入网格。

### 2.3 `AnimationClip`

至少包含：

- 动作名、持续时间、循环方式、目标帧数和播放模式。
- 骨骼关键帧、插值方式、局部缩放、透明度和层级切换。
- 事件轨道，例如闭眼、尾尖抽动、落脚和点击反应峰值。
- `time` 或 `distance` 相位来源。
- 首尾连续性约束和失败时的 fallback。

### 2.4 `RenderProfile`

首版固定：

- 逻辑画布 256×256；制作时允许 2 倍超采样后缩小。
- 单角色、单 Atlas、透明 RGBA。
- 固定帧求值顺序、颜色空间、缩放滤镜、PNG 编码参数和 Atlas 排序。
- 文件命名 `<action>_<index:03>`。
- 相同输入、模板、动画版本和种子必须生成字节级一致的测试产物。

## 3. 部件拆分与遮挡补全

单张照片或标准立绘无法提供所有被身体遮住的内容。拆分步骤必须区分“可见像素”和“推断
像素”，不能简单裁切后旋转，否则关节处会出现空洞。

处理顺序：

1. 将标准立绘归一到中性正面或轻微侧面姿势。
2. 生成身体、头、四肢、尾巴/头发和五官 Mask。
3. 每个部件向连接区域扩展安全重叠边缘。
4. 对被遮挡的肢体根部、身体后方、头发后层和尾巴根部执行受限补全。
5. 做 Alpha 去污染和边缘颜色扩展。
6. 检查部件重新合成后与原标准立绘的差异；超过阈值则拒绝进入绑定。

首轮开发不依赖 AI 拆分器：仓库保存不含私人照片的测试 LayerBundle 和预期合成图，用它
冻结 Schema、渲染和 QA。真实模型接入后只替换“标准立绘 → LayerBundle”步骤。

## 4. 模板骨骼

### 4.1 猫咪

骨骼层级：

```text
root
└─ torso
   ├─ head
   │  ├─ ear_l
   │  └─ ear_r
   ├─ front_leg_l → front_paw_l
   ├─ front_leg_r → front_paw_r
   ├─ hind_leg_l  → hind_paw_l
   ├─ hind_leg_r  → hind_paw_r
   └─ tail_01 → tail_02 → tail_03 → tail_04
```

猫咪先支持短毛标准体型。长毛和幼猫通过模板参数调整身体比例、脚长、尾巴幅度和部件覆盖，
不复制整套渲染代码。

### 4.2 人物

骨骼层级：

```text
root
└─ pelvis
   ├─ torso → head
   ├─ upper_arm_l → forearm_l → hand_l
   ├─ upper_arm_r → forearm_r → hand_r
   ├─ thigh_l → calf_l → foot_l
   └─ thigh_r → calf_r → foot_r
```

头发和衣摆作为附属骨骼跟随头部、躯干或骨盆，并使用较小幅度和相位延迟形成次级运动。
首版不制作独立手指骨骼。

## 5. 动作片段

### 5.1 猫咪动作

- `idle`：身体 2%–3% 呼吸缩放、轻微重心变化、一次眨眼、耳朵错相抖动、尾巴慢摆。
- `walk`：8 帧接触/下沉/经过/抬起循环，前后腿按猫步相位错开，头部保持相对稳定，
  尾巴以半个周期延迟平衡身体。
- `sleep`：四肢收拢、身体下沉、眼睛闭合、腹部慢呼吸、尾尖低频抽动；`zzz` 只是可选
  效果层，不能作为睡眠动作本身。
- `tap`：身体压缩后回弹、耳朵后压、眨眼和尾巴快速甩动，6–8 帧后回到 `idle`。
- `drag`：四肢收拢或轻微下垂，尾巴和耳朵按拖动方向产生有限惯性。
- `wake`：睁眼、抬头、前腿伸展和身体回升，结束后进入 `idle`。

### 5.2 人物动作

- `idle`：躯干呼吸、眨眼、头部微摆，头发和衣摆延迟跟随。
- `walk`：8 帧接触/下沉/经过/抬起循环，手臂与腿反向摆动，骨盆轻微横移和升降。
- `sleep`：切换到坐卧或蜷缩模板，闭眼、头部点动和呼吸；不能保持站姿只显示 `zzz`。
- `tap`：后仰或轻跳、眨眼、手臂短反应，随后回到 `idle`。
- `drag`：四肢保持安全姿势，头发和衣摆显示受限惯性。
- `wake`：抬头、睁眼和伸展；可选挥手使用独立 `wave` 动作并回退到 `idle`。

建议帧预算：

| 动作 | 帧数 | 建议帧时长 | 循环 |
|---|---:|---:|---|
| `idle` | 12–16 | 100–160 ms | 是 |
| `walk` | 8 | 70–110 ms 或距离相位 | 是 |
| `sleep` | 12–16 | 160–240 ms | 是 |
| `tap` | 6–8 | 60–100 ms | 否 |
| `drag` | 4–8 | 80–140 ms | 是 |
| `wake` | 8–12 | 80–130 ms | 否 |

## 6. 移动与脚步同步

走路动画不能只按墙钟推进，否则窗口移动速度与脚步不一致时会出现“滑冰”。桌面运行时需要
维护累计移动距离：

```text
walk_phase = (accumulated_distance / stride_length) mod 1
frame = floor(walk_phase * walk_frame_count)
```

- 自主移动和用户触发移动都更新累计距离。
- 窗口停止时冻结在最近的接触姿态，并在短过渡后回到 `idle`。
- 左右方向通过水平翻转同一套 Atlas，不重复存储另一方向。
- 改变速度只改变相位推进速度，不改变动作关键姿态。
- 尾巴、头发等次级运动烘焙在对应帧中，并与步态保持固定相位关系。

这需要为现有 Sprite 播放器增加可选的外部相位输入；普通 `idle/sleep/tap` 仍按帧时长播放。

## 7. 离线渲染与 Atlas

渲染器按固定时间或距离相位求值骨骼，合成所有部件并输出帧：

1. 应用根节点位移、骨骼变换和事件层。
2. 按当前 Z 顺序合成后层、身体、肢体、头部和前层。
3. 使用 2 倍超采样减少旋转锯齿，再缩小到逻辑画布。
4. 统一脚底锚点和角色中心，禁止每帧自动居中造成抖动。
5. 对透明边缘做颜色扩展，避免浅色和深色桌面出现光边。
6. 按动作名和帧号稳定排序后打包 Atlas。
7. manifest 记录帧顺序、时长、循环、下一动作和 fallback。
8. 打包后由现有 Rust 加载器重新读取并验证整个 `.epet`。

目标仍是单包不超过 30MB；优先减少空白边界和重复帧，不通过降低动作可辨识度来压缩。

## 8. 自动质量检查

每个 LayerBundle、Rig 和 Clip 至少检查：

- 部件缺失、重复 ID、父骨骼环、无效角度和越界锚点。
- 重新合成差异、关节裂缝、遮挡空洞和 Alpha 污染。
- 帧越界、脚底基线漂移、身体中心抖动和碰撞区域越界。
- 循环首尾的像素差、锚点差和骨骼角度差。
- 走路接触帧脚底滑移距离。
- 睡眠是否包含闭眼、姿势下沉/收拢和呼吸变化，不能只检测到 `zzz`。
- 猫咪尾巴和人物头发/衣摆是否存在次级运动，但幅度不能穿过身体。
- Atlas 引用、纹理边界、帧时长、fallback、文件哈希和包大小。

测试包含确定性单元测试、黄金帧图像比较、动作循环 GIF/帧带人工检查，以及桌面运行时实际
窗口移动录像。黄金素材只能使用内置原创测试角色。

## 9. 实施顺序

1. 冻结四个中间 Schema 和两套原创测试 LayerBundle。
2. 实现确定性部件合成、骨骼变换和 Atlas 渲染器。
3. 完成猫咪 `idle/walk/sleep/tap`，再补 `drag/wake`。
4. 接入桌面距离相位，验证脚步与窗口移动同步。
5. 完成人物 `idle/walk/sleep/tap`，再补 `drag/wake/wave`。
6. 加入黄金帧、循环接缝、脚滑、透明边缘和包加载测试。
7. 将 Mock Worker 改为调用动画流水线，产出真正多帧 `.epet`。
8. 完成上述基线后，再实施多硬件模型 Provider和真实标准立绘/部件拆分。

## 10. 完成标准

- 内置测试猫咪移动时四肢交替、身体起伏、尾巴摆动，脚步与实际窗口距离同步。
- 内置测试人物移动时手脚交替、身体升降、头发或衣摆有次级运动。
- 猫咪和人物睡眠均包含姿势、闭眼和呼吸变化，关闭 `zzz` 层后仍能辨认出睡眠状态。
- 六个动作均为多帧且循环无明显闪帧，非循环动作可平滑回到 fallback。
- 同一输入、模板和动画版本重复渲染得到相同 Atlas 与 `.epet` SHA-256。
- 生成包通过现有 Rust 安全校验、自动安装和激活，不破坏已有静态角色包。
- 256×256 目标画布下保持流畅播放，单包继续满足 30MB 限制。
