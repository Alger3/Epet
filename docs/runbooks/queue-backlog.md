# 队列积压运行手册

> 状态：Proposed
> 负责人：后端/AI 当值
> 评审人：后端负责人、产品负责人
> 最近更新：2026-07-24
> 更新触发：队列、Worker、阈值、扩缩容或预算策略变化

## 触发与确认

持续队列时间或最老任务年龄超过发布阈值。先按环境、步骤、工作流版本确认积压，排除指标延迟，并检查 PostgreSQL 快照与 Worker 租约。

## 止损

1. 若等待继续增长，关闭“新生成”；上传入口按原图保留能力决定是否同时关闭。
2. 不清空队列、不手改任务状态、不批量重试。
3. 对外显示服务状态；已安装宠物不受影响。

## 诊断与恢复

检查 Worker 在线/心跳、死信、数据库/对象存储延迟、单步骤错误率、GPU 容量和预算。修复根因后先放行测试任务，再有限扩容或恢复消费；确认版本乐观锁避免重复提交输出。等待时间和失败率稳定一个观察窗后逐步开启新生成。

## 结束条件

积压回到阈值内、无异常租约/重复输出、预算可控、用户状态恢复。记录起止时间、影响任务数、根因、操作、数据一致性检查和后续项。
