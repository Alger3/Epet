# 测试策略

> 状态：Active
> 负责人：测试负责人
> 评审人：桌面端负责人、后端/AI 负责人、安全负责人
> 最近更新：2026-07-24
> 更新触发：CI 车道、支持平台、Gate、数据集或核心风险变化

## 分层

| 层级 | 范围 | 默认频率 |
|---|---|---|
| 单元 | 状态机、坐标、解析、服务规则、Worker 纯步骤 | 每次提交 |
| 契约 | OpenAPI、Schema、生成类型、SSE 版本 | 每次提交 |
| 集成 | SQLite/PostgreSQL 迁移、对象存储、Redis、FastAPI | PR |
| 确定性 E2E | Mock Worker 完整闭环与故障注入 | PR |
| Windows | 窗口、DPI、多屏、睡眠、Explorer、安装升级 | 每个发布候选 |
| GPU 评估 | 冻结集质量、时间、成本和回归 | 每日/手动/发布候选 |
| 安全 | 恶意包、越权、脱敏、capability、更新签名 | PR 子集 + 发布全量 |

## CI 车道

- `fast-checks`：格式、类型、单元、Schema/OpenAPI、链接、秘密扫描。
- `desktop-build`：Windows 无签名构建和桌面测试，不读取签名密钥。
- `api-integration`：临时数据库、队列、存储和真实请求响应。
- `gpu-evaluation`：不阻塞普通 PR，发布候选必须通过冻结集。

## 确定性与数据

时间、随机、网络、磁盘、GPU 和队列故障必须可注入。测试保留随机种子。真实图片位于受控存储，仓库只保存合成/脱敏素材和 ID；探索集、冻结集和坏样例集严格分开。

## 发布证据

报告记录提交、环境、OS/GPU/驱动/WebView2、契约和模型版本、样本、原始结果、失败分类与 Artifact 链接。严重 Bug 必须增加回归测试；仅有人工口头确认不算证据。
